# media-studio — правила агента (Level 1)

Проект: Image Studio, этап 1 — изображения, облако (fal.ai). Полный план —
[PLAN.md](PLAN.md). Правила ниже обязательны и сужают глобальный
`~/.zcode/AGENTS.md` (Level 0).

## Границы

- Вся работа — внутри этого репозитория. Файлы вне него — только чтение.
- `projects/<p>/references/` — исходники заказчика: не изменять и не удалять.
- `projects/<p>/exports/` — финальные файлы: не перезаписывать без явной задачи.
- `generated/` — сырой ответ API, `working/` — промежуточные версии; ничего не
  «улучшать» на месте — новая версия = новый ассет с `parents`.

## Секреты

- Ключи только в переменных окружения (`FAL_KEY`). Имена — в `config/providers.yaml`.
- `.env`, `*.key`, `*.pem` не читать, не копировать, не коммитить: они в
  `.gitignore` и заблокированы PreToolUse-hook (`.zcode/config.json`).
  `.env.example` — можно.
- У ключей на стороне провайдера включить spending limits.

## Бюджет (до каждого платного вызова)

1. Оценка: `uv run python scripts/cost.py estimate --model <id> --count N`.
2. Оценка выше `confirm_threshold` (`config/budget.yaml`) → спросить пользователя
   (AskUserQuestion) и продолжать только после подтверждения.
3. Превышен дневной или проектный лимит → скрипт завершается с ошибкой — не
   обходить, доложить пользователю.
4. Ретраев не больше `max_retries_per_asset` (по умолчанию 3); каждый ретрай —
   снова через оценку бюджета.

## Принципы генерации

- Текст, логотипы, цены, CTA модель не рисует. Только детерминированное наложение
  через `scripts/compose.py` (HTML-шаблоны, P4).
- Консистентность — на reference-изображениях, не на seed. Seed — только для
  воспроизводимости, где поддерживается.
- Товар берётся с реального фото (`references/`) как reference; если нужна точная
  форма/цвет — генерировать окружение и композитить товар, а не просить модель
  его нарисовать.
- Цены, лимиты, обучение на данных и коммерческие условия провайдера проверять по
  документации (ссылки в `config/providers.yaml`), не по памяти.

## Структура и нейминг

- Проекты: `projects/<name>/` — `brief.md`, `references/`, `generated/`,
  `working/`, `exports/`, `manifest.json`.
- id ассета: `<project>-<prefix>-<NNNN>` (например `demo-img-0001`); `path` — от
  корня репо.
- Любой скрипт обязан проходить «пустой запуск» без поломки манифеста.

## Манифест

- Каждый созданный файл — запись в `projects/<p>/manifest.json` по схеме
  `schema/manifest.schema.json` (проверка: `scripts/qc_image.py --manifest ...`).
- Формат записи фиксирован и рассчитан на этап 2 (видео добавит `type: "video"`
  без изменения формы записи). Новые поля — только через изменение схемы + ADR.
- Dry-run записи: `cost_usd: 0`, планируемая сумма — в `params.planned_cost_usd`.

## QC

Три уровня: детерминированный (`qc_image.py`) → визуальный (агент читает
изображение через Read) → человек (утверждение перед копированием в `exports/`).
Цикл FAIL → правка → повтор — не больше `max_retries_per_asset` и в рамках бюджета.

## Разработка

- Python ≥ 3.11, окружение uv (`uv sync`). Зависимости — в `pyproject.toml`.
- Перед коммитом: `uv run ruff check .` и `uv run pytest -q` (те же команды — в
  `.zcode/project.yaml`).
- Коммиты — Conventional Commits; push и merge в main — только с явного
  разрешения пользователя.
- Скиллы (`.zcode/skills/`) — тонкие инструкции к скриптам; правила живут здесь.
