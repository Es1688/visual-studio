# ADR-0004: Профили типов проектов

Статус: accepted (2026-10-13)

## Контекст

Студия остаётся универсальной (баннеры, обложки, карточки, фото), но отдельным
направлениям нужна специализация: методология карточек товара для маркетплейсов
(см. docs/methodology/marketplace-card.md) должна работать только в каталоге
`projects/marketplace`. В перспективе появятся каталоги под аватарки, сайты и
работу с фото. Специализировать скрипты студии ветками под каждое направление —
расходящийся оверрайт универсального ядра.

## Решение

Опциональный `projects/<p>/profile.yaml`: поле `type`
(marketplace | avatars | websites | photo | …) плюс данные типа (для
marketplace — параметры площадок и banned-фразы). Чтение —
`studio_common.load_profile(project)`. Скрипты студии остаются универсальными;
специализированный функционал (скилл marketplace-card, `qc_image.py
--marketplace`) активируется двойным гейтом: проект называется `marketplace`
И `profile.type == marketplace` — иначе отказ (exit 2) с пояснением. Профиль и
шаблоны каталога — локальные артефакты проекта (projects/ в .gitignore); в git
уходит только механизм (код, скилл, ADR, тесты).

## Последствия

- Плюс: специализация в одном месте — каталоге типа; универсальное ядро не
  обрастает ветками; новые типовые каталоги добавляются профилем + тонким
  скиллом по той же схеме.
- Минус: гейт привязан к имени проекта — второй маркетплейс-каталог потребует
  явного расширения списка имён (сознательно, до согласования с пользователем).
- Future: каталоги avatars/websites/photo по той же схеме; при частых заказах
  в одном манифесте — тег order в params (через изменение схемы + ADR).
