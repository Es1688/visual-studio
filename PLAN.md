# Visual Studio — план этапа 1: Image Studio (доработан под ZCode)

Статус: P0 (каркас) собран. Дата доработки: 2026-10-06.
Зафиксированные решения: провайдер — **fal.ai** (ADR-0001), compose — **HTML/CSS + Playwright**
(ADR-0003), манифест — JSON per project (ADR-0002). Репозиторий = этот workspace
(`visual-studio` — имя проекта в конфигах; каталог репозитория переименован с
`visual studio` на `visual-studio` 2026-10-06).

---

## 1. Смысл этапа

Этап 1 даёт законченную ценность сам по себе: рекламные картинки, баннеры, превью —
и закладывает общую основу (манифест, бюджет, интерфейс провайдеров, QC-каркас),
на которую в этапе 2 ляжет видео. Видеоспецифику не трогаем.

**Входит:** text→image; image→image и редактирование по reference (товар, стиль,
персонаж); inpainting / правка областей; удаление фона; upscale; ресайз, кроп,
конвертация, пресеты площадок (1:1, 4:5, 9:16, 16:9); детерминированное наложение
текста, логотипа и CTA; превью (thumbnails) и рекламные баннеры.

**Не входит (этап 2):** видеогенерация, FFmpeg-монтаж, Kinocut, Remotion, аудио,
субтитры, storyboard роликов, batch по видео. ComfyUI остаётся опциональным и в
этап 1 не попадает. MCP не настраиваем.

## 2. Архитектура в ZCode

Исходный план писался под Claude Code; здесь — замены и дополнения под механику ZCode:

| Было | Стало в ZCode |
|---|---|
| `CLAUDE.md` | `AGENTS.md` в корне репо — workspace-инструкции Level 1; глобальный `~/.zcode/AGENTS.md` (Level 0) грузится раньше и не дублируется |
| `skills/` в корне проекта | `.zcode/skills/<name>/SKILL.md` — версионируются с репо; доступны как слэш-команды (`/image-generate`) и срабатывают автоматически по описанию |
| «deny-правила агента» для `.env` | `.gitignore` + **PreToolUse-hook** в `.zcode/config.json` (`hooks.enabled: true`): скрипт `scripts/hooks/deny_secrets.py` возвращает exit 2 (deny) на обращения к `.env` / `*.key` / `*.pem` |
| Подтверждение расходов «при превышении порога» | оценка через `cost.py estimate`; выше `confirm_threshold` из `config/budget.yaml` → агент спрашивает пользователя (AskUserQuestion); превышение дневного/проектного лимита — жёсткий отказ скрипта (не обходить) |
| Визуальный QC «vision-проверка» | агент читает изображения нативно (Read) по инструкции скилла `image-qc`; отдельный vision-MCP не нужен |
| — | `.zcode/project.yaml` — манифест Engineering Hub: quality-checks (`ruff`, `pytest`), ограничения проекта |
| — | архитектурные решения — короткие ADR в `docs/adr/` |
| MCP «если позже понадобится» | слот известен заранее: `.zcode/config.json` → `mcp.servers`; в этапе 1 пусто |

Разделение ролей:

- **AGENTS.md** — правила проекта: границы доступа, секреты, бюджет, принципы
  генерации, структура/нейминг, манифест, QC. Единственное место правил.
- **Скиллы (3 шт.)** — тонкие инструкции: когда применять → какой скрипт вызвать →
  куда сохранить → как проверить → что делать при ошибке. Правила не дублируют.
- **Скрипты (`scripts/`)** — детерминированный слой; агент вызывает их через bash.
  Каждый скрипт пишет в манифест в одном формате.
- **Hook** — единственный принудительный механизм (секреты); остальное —
  дисциплина по AGENTS.md + жёсткие проверки в скриптах.

## 4. Провайдеры

Провайдер этапа 1 — **fal.ai** (ADR-0001): text→image (FLUX), редактирование по
reference (FLUX Kontext), inpainting (FLUX Fill), upscale, удаление фона — за одним
queue-API и одним ключом. Интерфейс `gen_image.py` провайдеро-независимый; P2
добавляет вторую модель/провайдер без правок скиллов.

Обязанность перед первым платным запуском (для каждой модели, по документации,
не по памяти): актуальная цена, лимиты, политика обучения на данных, условия
коммерческого использования, контент-фильтры. Результат проверки — заметка в
`config/providers.yaml`.

**Статус проверки (2026-10-06, выполнено):** цены и единицы тарификации
сверены по докам fal.ai и зафиксированы в `capabilities.yaml`: flux-dev и
flux/dev/fill — **$0.025 за мегапиксель** (не за картинку), kontext —
$0.04/картинку, clarity-upscaler (эндпоинт переименован!) — $0.03/МП выхода,
birefnet/v2 — заявлен бесплатным (проверить первое списание). Политика
(хранение 1/30 дней по тарифу, NSFW-фильтр по умолчанию, обучение на данных —
запрещено в MSA, лимиты по конкурентности) — в `config/providers.yaml`.
Оценка в `cost.py` учитывает единицу тарификации: per-MP считается по
фактически запрашиваемым пикселям пресета.

Секреты: только env (`FAL_KEY`). `.env` закрыт `.gitignore` + hook; у ключей
на стороне провайдера включить spending limits.

## 5. Манифест ассета

Один `manifest.json` на проект, схема — `schema/manifest.schema.json`, проверка —
`qc_image.py --manifest`. Каждая запись: `id, path, type, provider, model,
api_version, operation, prompt, seed?, params, parents[], cost_usd, created_at,
qc{status}, dry_run?`.

Пример:

```json
{
  "id": "demo-img-0001",
  "path": "projects/demo/generated/demo-img-0001.png",
  "type": "image",
  "provider": "fal",
  "model": "flux-dev",
  "api_version": null,
  "operation": "text_to_image",
  "prompt": "cozy autumn morning, wooden table, warm light, product space",
  "seed": 42,
  "params": { "aspect": "square", "count": 1, "ref_images": [] },
  "parents": [],
  "cost_usd": 0.025,
  "created_at": "2026-10-06T18:00:00+00:00",
  "qc": { "status": "pending", "checks": [] }
}
```

Формат фиксирован и рассчитан на этап 2: видео добавится как `type: "video"` без
изменения формы записи; новые поля — только через изменение схемы + ADR. Dry-run
записи имеют `cost_usd: 0` (планируемая сумма — в `params.planned_cost_usd`),
чтобы не искажать учёт расходов.

## 6. Скрипты (детерминированный слой)

| Скрипт | Назначение | Стадия |
|---|---|---|
| `gen_image.py` | `--project --prompt --model --aspect [--seed] [--ref ...] [--count] [--dry-run]`: оценка → бюджет → генерация → `generated/` + манифест; адаптеры провайдеров, submit/poll/download, ретраи | готов (P1) |
| `edit_image.py` | `--asset --mode edit\|inpaint\|remove_background [--prompt] [--mask] [--ref ...] [--aspect]` | готов (P3) |
| `upscale.py` | `--asset [--scale] [--model esrgan]` | готов (P3) |
| `compose.py` | `--project --asset --template --data --ratio 1x1,4x5,9x16`: наложение текста/логотипа/CTA по HTML-шаблону (Playwright) | готов (P4) |
| `export.py` | `--asset --preset square_1x1\|portrait_4x5\|portrait_9x16\|landscape_16x9 [--format png\|jpg\|webp] [--quality]` | готов (P1) |
| `qc_image.py` | `--manifest \| --project [--min-side] [--min-std]` + `--asset --set-status pass\|fail\|retry`: детерминированные проверки (схема, разрешение, aspect, не однотонное) и фиксация QC-решений | готов (P0–P5) |
| `cost.py` | `estimate --model [--count] [--aspect]` / `spend --project [--today]` / `check --project [--planned USD]` | рабочий |
| `batch.py` | `--project --csv [--concurrency] [--dry-run] [--limit]`: очередь из CSV, префлайт-бюджет партии, отчёт в `logs/batch-*.json` | готов (P6) |
| `hooks/deny_secrets.py` | PreToolUse-гард: deny на `.env`/`*.key`/`*.pem` | P0 |

Общее — в `scripts/studio_common.py` (конфиги, манифест, бюджет, id ассетов).
Все скрипты пишут в манифест в одном формате.

## 7. Skills (три, не больше)

Тонкие SKILL.md в `.zcode/skills/` — «когда применять → какой скрипт → куда
сохранить → как проверить → при ошибке». Правила проекта (структура, нейминг,
бюджет, секреты, принципы) живут в AGENTS.md и не дублируются.

- **image-generate** — бриф → промпт → модель по `capabilities.yaml` → оценка →
  генерация → манифест. Активен с P1.
- **image-edit** — reference-генерация, inpainting, upscale, удаление фона, ресайз
  и конвертация. Активен с P3.
- **image-qc** — три уровня QC и решение pass/fail/retry. Частично с P1, полный с P5.

## 8. Принципы этапа 1

1. Текст, логотип, цены, CTA — только детерминированно (`compose.py`, HTML-шаблоны).
   Модель их не рисует.
2. Товар берётся из реального фото (`references/`) и подаётся как reference. Если
   нужна точность формы и цвета — генерировать окружение и композитить товар, а не
   просить модель его нарисовать.
3. Консистентность строится на reference-изображениях, а не на seed. Seed — только
   для воспроизводимости там, где поддерживается.
4. Оценка стоимости до запуска; выше порога — подтверждение пользователя
   (AskUserQuestion); превышение дневного лимита — жёсткий отказ скрипта.
5. Ретраи ≤ `max_retries_per_asset` (3) на ассет; каждый ретрай — через оценку бюджета.
6. Секреты только в env; `.env` заблокирован hook'ом; у ключей лимиты на стороне
   провайдера.
7. Приватность и цены: перед выбором модели проверять обучение на данных,
   коммерческие условия и контент-фильтры по документации провайдера.

## 9. QC для изображений

1. **Детерминированный** (`qc_image.py`): валидность манифеста; разрешение,
   aspect ratio, формат, размер файла; не пустое/не однотонное; safe zones площадок.
2. **Визуальный** (агент, Read изображения): артефакты (руки, лишние объекты,
   искажения), соответствие брифу и reference, различимость текста после наложения.
3. **Человек**: утверждение финала перед копированием в `exports/`.

Цикл FAIL → исправление → QC ограничен `max_retries_per_asset` и бюджетом.

## 10. Порядок работ

**P0. Каркас (готово).** Структура, AGENTS.md, hook-запрет `.env`,
`.zcode/project.yaml`, скиллы, `config/*.yaml`, схема манифеста, скрипты
(dry-run/заглушки), тесты, git.
Готово, когда: hook отклоняет чтение `.env`; `ruff` + `pytest` зелёные;
`gen_image.py --dry-run` пишет валидную запись в манифест; `cost.py check`
работает; пустой запуск не ломает манифест.

**P1. Вертикальный срез.** Проверить цены/условия fal.ai по докам и зафиксировать
в `capabilities.yaml`/`providers.yaml`. Адаптер fal.ai в `gen_image.py`
(submit/poll/download queue API, ретраи), минимальные `export.py` и `qc_image.py`,
скилл `image-generate`.
Готово, когда: из брифа получается изображение в нужном формате, с записью в
манифест и стоимостью; `/image-generate` срабатывает из чата.
**Статус: код готов, цены проверены (2026-10-06)** — `fal_adapter.py`, реальный
режим `gen_image.py`, `export.py`, `qc_image.py`; весь HTTP покрыт моками.
Платный прогон — при `FAL_KEY`.

**P2. Вторая модель/провайдер за тем же интерфейсом** + выбор по
`capabilities.yaml` (цена/возможности).
Готово, когда: смена модели = один флаг `--model`; скиллы не меняются.
**Статус: выполнено** — пять моделей за одним адаптером, выбор флагом `--model`
по `capabilities.yaml` (единицы тарификации и аспекты — в конфиге); скиллы не
зависят от модели.

**P3. Редактирование.** reference, inpainting, upscale, удаление фона; скилл
`image-edit`.
Готово, когда: товар из реального фото сохраняется узнаваемо в новом окружении.
**Статус: код готов** (`edit_image.py` три режима, `upscale.py`; моки). Критерий
узнаваемости проверяется платным прогоном.

**P4. Compose.** `templates/*.html` (текст/логотип/CTA — data-поля), рендер
Playwright (headless Chromium; зависимость добавляется здесь), скилл в составе
`image-edit`.
Готово, когда: один бриф даёт баннер в нескольких aspect ratio с одинаковым текстом.
**Статус: готов** — Chromium установлен, шаблон визуально проверен; сквозной
прогон demo: один бриф → 3 формата с одинаковым текстом (demo-cmp-0003…0005).

**P5. Полный QC** (три уровня, §9) и скилл `image-qc`; цикл FAIL→retry в лимитах.
**Статус: готов** — детерминированные проверки и фиксация решений
(`qc_image.py --set-status`); визуальный уровень выполняет агент по скиллу;
финал утверждает человек перед `exports/`.

**P6. Серия.** Batch из CSV: очередь, лимит конкурентности, бюджет на партию;
запуск можно уводить в фоновую bash-команду.
Готово, когда: 20 баннеров проходят pipeline в рамках бюджета, а golden-набор из
5–10 брифов даёт стабильный результат при смене модели.
**Статус: код готов** (`batch.py`: префлайт-бюджет, конкурентность, отчёты в
`logs/`; golden-набор `projects/demo/golden.csv` — 8 брифов ≈ 0.29 USD).
Реальный прогон партии — при `FAL_KEY`.

## 11. Итоговый критерий этапа 1

По брифу и фото товара студия выдаёт 3 варианта баннера в 3 форматах с корректным
текстом и логотипом, прошедших QC, с манифестом и точным учётом расходов, укладываясь
в заданный бюджет.

**Статус:** офлайн-доказано на demo (3 формата, текст/CTA наложены, QC pass,
манифест и бюджет учтены, 0 USD — все операции локальные). Полный платный
критерий (3 варианта × 3 формата с реальной генерацией) — после настройки
`FAL_KEY`.

## Приложение: работа в ZCode

- Скиллы доступны как слэш-команды (`/image-generate`) и срабатывают автоматически
  по формулировке запроса.
- Дорогие запуски: `cost.py estimate` → выше порога → агент показывает оценку и
  варианты (AskUserQuestion) → подтверждение → запуск.
- Batch (P6) можно запускать фоновой командой и продолжать работу в сессии.
- Hook в `.zcode/config.json` блокирует любые обращения к `.env`/`*.key`/`*.pem`;
  это последняя линия защиты после AGENTS.md и `.gitignore`.
- Перед коммитом: `uv run ruff check .` и `uv run pytest -q` (те же команды — в
  `.zcode/project.yaml`, блок quality); коммиты — Conventional Commits; push —
  только с явного разрешения пользователя.
