# image-qc

Статус: реализован (P5): детерминированные проверки (`qc_image.py`, включая
записи без файлов — «planned») и фиксация решений через `--set-status`;
визуальный уровень выполняет агент, финал перед `exports/` утверждает человек.

1. **Детерминированный**: `uv run python scripts/qc_image.py --project <p>`
   (или `--manifest <path>`): валидность манифеста; с P1 добавляются разрешение,
   aspect ratio, формат, размер файла, не пустое/не однотонное, safe zones площадок.
2. **Визуальный** (агент): прочитай изображение через Read и проверь по чек-листу:
   - артефакты: руки, пальцы, лишние объекты, искажения, битые тексты модели;
   - соответствие брифу (сюжет, стиль, формат) и reference (узнаваемость товара);
   - после compose — различимость и корректность наложенного текста/CTA/логотипа.
   Результат зафиксируй в манифесте: `qc.status = pass | fail | retry` и краткие
   `qc.checks`.
3. **Человек**: финал перед копированием в `exports/` утверждает пользователь —
   покажи варианты и получи явное одобрение (AskUserQuestion).

Цикл FAIL → исправление → повтор: не больше `max_retries_per_asset` (по умолчанию 3)
и в рамках бюджета (`cost.py check`); каждый ретрай — новая версия ассета с `parents`,
а не перезапись. Правила — в AGENTS.md, стадии QC — в PLAN.md §9.
